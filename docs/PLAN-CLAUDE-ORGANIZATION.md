3. **034 веќе има programme/placement и одделени годишни факти.** Не гради

## Прв пакет за Claude Code — само preflight алатка и тестови

Цел: да го подготви чекор 2 од доставеното упатство без промена на живи податоци.

1. Направи мала CLI алатка и npm команда `check:organization` во `server/`.
   Користи постојни конвенции за конфигурација. Сите SQL читања нека бидат во
   една `REPEATABLE READ READ ONLY` трансакција. Нема `--apply`, DDL, backfill,
   поправки или автоматско поврзување лица.
2. Провери **сите учебни години**, не само тековната:
   - паралелка со повеќе од еден `homeroom` наставник;
   - наставник со `homeroom` задолжение во повеќе паралелки во иста година;
   - повторени доделувања на категорија, одделно по вид профил и заедно.
     Последново е информативен наод, НЕ грешка само затоа што професијата се
     повторува. Прикажи активност и разликувај профили од потврдени лица.
3. Работи на шема 032 и на 036: провери достапност на новите колони во
   тековниот search_path, без да чита/мигрира друга шема. На 032 кажи дека
   поврзување преку employee_id не е достапно. Не заклучувај дека еднакви имиња
   значат ист човек. Не го прикажувај недостапниот податок како нула.
4. Извештајот нека содржи логичка инсталација, име на база, schema version,
   година, бројки и технички ID. Без имиња, credentials или DATABASE_URL.
   Ако нема поврзување, пријави оперативна грешка, не „нема неправилности“.
   Разликувај exit codes за успешно читање, оперативна грешка и homeroom наод;
   документирај ги и тестирај ги. Повторена професија сама не е неуспех.
5. Тестови со измислени податоци: чист случај, секое homeroom прекршување,
   прекршување само во архивска година, повеќе subject наставници дозволени,
   исти задолженија во различни години дозволени, повторена професија,
   потврден заеднички employee_id, шеми 032/036 и неуспешно поврзување.
   Докажи дека проверката ги забележува намерно внесените прекршувања.
6. Не пуштај тестови што пишуваат врз живата HOME/WORK/Supabase база.
   Интеграциски тестови само во експлицитна disposable база/изолирана шема со
   проверена конфигурација. `MTB_SCRATCH_DB=1` не ја прави живата база безбедна.
7. Забележан тест-долг: `server/test/migrations.e2e.ts` сè уште очекува 33
   миграции. При користење на овој тест усогласи ја проверката со вистинскиот
   ledger, не прескокнувај неуспех и не тврди дека сите миграции се тестирани
   ако пакетот не бил извршен. Поправката не смее да ја ослаби atomicity проверката.

**Крај на првиот пакет:** предај код, тестови, краток резултат и предлог за
следната адитивна миграција. Не ја создавај/применувај миграцијата во овој пакет.
Не оди самостојно на следна фаза. Ова остава мал diff за Codex да го дебагира.

## Следни пакети — одделно одобрување и преглед

1. По preflight и одобрување: двете homeroom уникатности во нова миграција,
   сите writer патеки и разбирливи API грешки. Архивските судири се пријавуваат;
   не се бришат. Тестови за конкурентни запишувања и пад пред/успех по чуварот.
   Третата, категориска уникатност останува одделна доменска одлука.
2. Професија и годишно задолжение во постојната администрација: предлог што
   ја користи 035, ги опфаќа модифицирана настава со надворешни ученици и
   подготвителна група, а не создава терапевт само за да запише професија.
   Конкретните назначувања се приватни податоци, не seed миграции.
3. Извештај за ученички конфликти по вистински минути: провери го актуелниот
   view/API, изброј ги читачите и зачувај го API договорот. Користи ја
   постојната аритметика; не создавај паралелен SQL/JS пресметувач без одобрен
   дизајн. Тестирај 40′ наспроти 20′, соседни непреклопени половини и различни денови.
4. Конфликт на вработен настава ↔ кабинет преку потврден employee_id,
   без нов идентитетски модел; потоа структурен тип на паралелка.
   Типот не се извлекува од `class_years.description`.
5. Групни сесии: посебен дизајн пред код. Не ослабувај overlap guards.
6. Подгодишна историја, па верзионирање: посебни proposals, сите читачи,
   expand → backfill → постепено префрлање → contract. S-Dnevnik и реализацијата
   не се препишуваат од планираниот распоред.

## Предавање од Claude Code и проверка од Codex

Claude Code да остави кратка белешка без лични податоци:

- почетен/краен HEAD, `git status`, список на изменети фајлови;
- што е завршено и што намерно е оставено;
- точни тест-команди и резултати, вклучувајќи непуштени/блокирани тестови;
- дали е читана жива база и потврда дека нема live writes/migrations/deploy;
- најмногу три отворени прашања.

Codex потоа го проверува само предадениот diff и ризичните соседни патеки:
read-only гаранцијата, сите години, scope на шема, приватност, разлика професија/
кабинет/улога, лажни нулти резултати и регресии. Репродуцира тестови во безбедна
средина, дебагира, па дава одлука за следниот пакет — не за автоматски deploy.

Основни проверки од `server/`: `npm run typecheck`, `npm test`, новите тестови
за пакетот и `npm run check:names`. Провери и нови/untracked фајлови: скен што
чита само Git-tracked фајлови не ги покрива автоматски. Browser пакетите се
пуштаат според погодените екрани, само со изолирани/измислени податоци.

Нема push, deploy, промена на .env, sync или продукциска миграција без посебно
барање. Не работат два агента истовремено врз истите фајлови. Ако има туѓи
измени, зачувај ги и пријави преклопување; не reset/checkout. Пред следен
пренос меѓу машини, сопственикот нека побара проверен commit/push на handover-от.
