# ИЗВЕШТАЈ ОД ИСТРАГА: Каде исчезнуваат екстерните ученици во екранот „Додели ученици“ на машини без база

- **Датум:** 11 септември 2026
- **Репозиториум:** `MTB` (гранка `main`, комит `4ba1e17`)
- **База на податоци:** PostgreSQL 18 (`therapy_dev`)
- **Статус на извештајот:** Истрага без модификација на код или податоци (Read-only investigation)

---

## 1. Резиме и краток одговор (TL;DR)

Екстерните ученици (16 ученици во 2026/2027 со `kind = 'external'` и `grade = NULL`) **не се избришани од базата**, но во екранот за штиклирање на ученици за терапевт на машини без база (офлајн преку JSON) стануваат **навидум невидливи** поради комбинација од четири фактори:

1. **`RasporediFusion.html` нема офлајн режим:**  
   Екранот за кој во кодот постои ознака `(екст.)` (`RasporediFusion.html`, линии 1475–1483) зависи 100% од базата преку `/api/roster`. На машина без база, `RasporediFusion.html` воопшто не се отвора / прикажува грешка („Нема врска со базата“), бидејќи нема функционалност за вчитување на JSON.
2. **На машини без база се користи `Rasporedi.html` (legacy JSON fallback):**  
   Во `Rasporedi.html`, функцијата за штиклирање на ученици на терапевт е `loadTherapistStudentsCheckboxes()` (линија 4448). Таа ги групира сите ученици според нивното одделение.
3. **Групата „Без одделение“ се сортира на самото дно под IX одделение:**  
   Бидејќи екстерните ученици имаат `grade = null` (односно празен стринг `""`), тие се сместуваат во група со наслов **`„Без одделение“`**. Функцијата `gradeRank()` (линија 4029) на оваа група ѝ доделува ранг **`500`**, поради што таа се исцртува **најдолу под сите паралелки од I до IX**. При долг список, корисникот вообичаено не скрола до крај и смета дека учениците ги нема.
4. **Полето `kind` никогаш не се извезува во JSON:**  
   Полето `kind` постои само во релационата табела `student_enrollments` во PostgreSQL. Скриптата `export-json.ts` (линии 208, 243–249) чита директно од табелата `students` и во `studentMeta` запишува само `{ grade, studentId }`. Поради тоа, во JSON експортот екстерните ученици немаат ниту `kind: "external"`, ниту училиште на потекло (`school`), ниту чип со ознака. Дополнително, пребарувањето по клучен збор „екст“ во полето за пребарување враќа 0 резултати.
5. **Втор можен симптом (Кеш при извоз):**  
   Доколку извозниот JSON фајл е извезен преку прелистувачот во `Rasporedi.html` (`exportJSONBackup()`) пред корисникот на работниот компјутер да притисне „Вчитај од сервер“, локалниот кеш во `localStorage` содржел само 62 ученици (старата состојба од минатата година пред роловерот), па екстерните воопшто не ни стигнале во извезениот фајл.

## 2. Одлучувачка проверка на податоците (Точни броења)

Направена е директна проверка на податоците во базата и во генерираните извозни структури:

### А. Во релационата база (`therapy_dev`):
```sql
SELECT e.kind, COUNT(*) 
FROM student_enrollments e 
JOIN school_years y ON y.id = e.school_year_id 
WHERE y.is_current = true AND e.active = true 
GROUP BY e.kind;
```
- **Вкупно активни запишани ученици во 2026/2027:** **78**
  - `kind = 'internal'`: **46** (сите имаат пополнето `grade`)
  - `kind = 'boarding'`: **16** (сите имаат пополнето `grade`)
  - `kind = 'external'`: **16** (сите имаат `grade IS NULL`)
- **Вкупно ученици во матичната табела `students`:** **100** (78 активни во тековната година + 22 од минати години).

### Б. Во базата на апликативни состојби (`app_state WHERE app = 'unified'`):
- **Вкупно ученици во `payload.students`:** **100**
- **Ученици со празно/null одделение:** точно **16**
- **Ученици со `kind = 'external'`:** точно **0** (својството `kind` воопшто не постои во JSON структурата).

### В. Во извезениот фајл `UnifiedSync-from-postgres-*.json` (`server/scripts/export-json.ts`):
- **Вкупно ученици во низата `students`:** **100** (вклучувајќи ги сите 16 екстерни и 22 неактивни)
- **Ученици со `studentMeta[name].grade === ""`:** точно **16**
- **Ученици со својство `kind`:** точно **0** (полето не се извезува).

## 3. Анализа на извозот (Export Pipeline)

### Скрипта: `server/scripts/export-json.ts`
- **Линија 208:**
  ```typescript
  const { rows: studentRows } = await client.query(
    `SELECT id, public_id, sdnevnik_id, name, grade, active, plan_id
     FROM students
     ORDER BY name`
  );
  ```
- **Линии 243–249:**
  ```typescript
  const studentMeta: Record<string, { grade: string; studentId: string }> = {};
  for (const s of studentRows) {
    studentMeta[s.name] = {
      grade: s.grade || '',
      studentId: s.public_id,
    };
  }
  ```
- **Наод:**  
  1. Нема филтрирање што ги отфрла учениците со празно или `null` одделение. Сите ученици влегуваат во списокот.
  2. Упитот се извршува над табелата `students`, а не над `student_enrollments`. Бидејќи колоната `kind` постои само во `student_enrollments` (воведена со миграција `028_kind_matches_grade.sql`), полето `kind` воопшто не се селектира.
  3. `studentMeta` не ги содржи полињата `kind`, `school`, ниту `category`. За екстерните ученици се запишува само `grade: ''`.

### Прелистувач: `Rasporedi.html` -> `exportJSONBackup()`
- **Линија 6597:** Повикува `currentStateSnapshot()`.
- **Линии 6546, 6743:** Ја зема моменталната состојба од меморијата на прелистувачот (`students` и `studentMeta`).
- **Наод:**  
  Ако корисникот на работниот компјутер со база направил извоз пред да кликне „Вчитај од сервер“ (или ако претходно немал синхронизирано преку `localSrvPull`), во неговиот `localStorage` стоела состојбата од минатата година (со 62 ученици). Во тој случај, извезениот JSON содржи само 62 ученици, а новите 16 екстерни целосно отсуствуваат од фајлот.

## 4. Анализа на вчитувањето (Import Pipeline)

### Датотека: `Rasporedi.html`
- **Линии 5775–5780 (`applyUnifiedPayload`):**
  ```javascript
  if (Array.isArray(data.students)) {
      students = data.students.filter(s => typeof s === 'string' && s.trim());

  }
  ```
- **Линија 5801 (`ensureStudentMeta`):**
  ```javascript
  function ensureStudentMeta() {
      if (!studentMeta || typeof studentMeta !== 'object') studentMeta = {};
      students.forEach(s => {
          if (!studentMeta[s]) {
              studentMeta[s] = { grade: '' };
  ```

- **Наод:**  
  1. При вчитување на JSON-от, нема никакво филтрирање по одделение.

  3. За сите ученици што имаат празно или недефинирано одделение, метаподатоците се поставуваат на `{ grade: '' }`. Ниту еден ученик не се губи во чекорот на парсирање.

## 5. Анализа на однесувањето кога нема база (Офлајн режим)

Во репозиториумот постојат две апликации за распоред:

| Апликација | Како работи со база? | Како работи БЕЗ база (офлајн)? |
|---|---|---|
| **`RasporediFusion.html`** (Канонска апликација според `APP-CONTRACT.md`) | Чита директно од `/api/roster`. Има поддршка за `(екст.)` и `(инт.)` во модалот на линии 1475–1483. | **НЕ РАБОТИ ВОЗМОЖНО.** Нема поддршка за вчитување JSON. Ако серверот/базата не одговори, прикажува грешка и блокира. |

## 6. Точна дијагноза: Каде и зошто екстерните ученици „исчезнуваат“ во `Rasporedi.html`?

Во `Rasporedi.html`, интерфејсот за штиклирање на ученици на терапевт се генерира преку функцијата `loadTherapistStudentsCheckboxes()`:

### А. Кодот за групирање (линии 4483–4488):
```javascript
const groups = new Map();
visible.forEach(s => {
    const key = getStudentCategory(s) === 'preschool' 
        ? 'Предучилишна' 
        : (getStudentGrade(s) || 'Без одделение');
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key).push(s);
});
```
- За екстерните ученици, `getStudentCategory(s)` враќа `""` (бидејќи нема поле `category`).
- `getStudentGrade(s)` враќа `""` (бидејќи `grade` е `NULL`).
- Како резултат на ова, сите 16 екстерни ученици се сместуваат во група со назив:  
  **`"Без одделение"`**.

### Б. Кодот за сортирање на групите (линии 4029–4048 и линија 4491):
```javascript
function gradeRank(grade) {
    const g = normalizeGrade(grade);
    if (!g) return [999, 999, ''];
    const m = g.match(/^(VIII|VII|VI|IX|IV|III|II|X|V|I)(?:-([абвгд]))?$/i);
    if (!m) return [500, 500, g];
    const roman = m[1].toUpperCase();
    const section = (m[2] || '').toLowerCase();
    return [ROMAN_GRADE_ORDER[roman] || 500, section ? (SECTION_ORDER[section] || 500) : 0, g];
}
```
- Римските одделенија од I до IX добиваат ранг од 1 до 9.
- Стрингот `"Без одделение"` не се совпаѓа со римските бројки, па добива ранг **`500`**.
- При сортирањето:
  ```javascript
  const order = [...groups.keys()].sort((a, b) => compareGrades(a, b) || a.localeCompare(b, 'mk'));
  ```
  Групата `"Без одделение"` се пласира **на најдолното дно на целиот екран**, после сите одделенија од I до IX.

### В. Визуелниот приказ на редот (линија 4500 и 4226):
```javascript
function studentGradeChipHtml(student) {
    const grade = getStudentGrade(student);
    return grade ? `<span class="student-grade-chip">${escapeHtml(grade)}</span>` : '';
}
```
- Кај екстерните ученици, чипот за одделение е целосно празен (`''`). Нема индикатор за матично училиште, ниту пак ознака `(екст.)`.

### Г. Филтерот за пребарување (линија 4468):
```javascript
return `${displayStudentName(s)} ${getStudentGrade(s)} ${getStudentSchool(s)}`
    .toLocaleLowerCase('mk-MK')
    .includes(query);
```
- Доколку терапевтот се обиде во полето за пребарување да напише „екст“, „екстерен“ или името на другото училиште, филтерот враќа 0 резултати, бидејќи во `studentMeta` тие информации воопшто не постојат.

## 8. Препораки за идно решение (За одлука на тимот)

Согласно правилото *„Ништо не менувај, поправката ја одлучува човек“*, подолу се предлозите за трајно надминување на овој дефект:

### Предлог 1: Адитивно проширување на извозот (Согласно Правило 4 од `AGENTS.md`)
Во `server/scripts/export-json.ts` (и соодветно во `import-core.ts` / `buildUnifiedSyncPayload`), при генерирање на `studentMeta`, да се направи `LEFT JOIN` со `student_enrollments` за тековната година:
```typescript
studentMeta[s.name] = {
  grade: s.grade || '',
  studentId: s.public_id,
  kind: s.kind || 'internal',        // Адитивно ново поле
  school: s.school_origin || ''       // Адитивно ново поле
};
```
*Ова нема да скрши ниту една стара верзија (правило за компатибилност), а ќе ги зачува информациите за офлајн машините.*

### Предлог 2: Подобрување на приказот во `Rasporedi.html`
Во `Rasporedi.html` (линија 4485):
1. Ако ученикот има `meta.kind === 'external'` или е во групата без одделение, групата да се именува **`„Екстерни ученици“`** наместо „Без одделение“.
2. На групата „Екстерни ученици“ да ѝ се додели логичен ранг (на пример веднаш по предучилишна или пред прво одделение, или со јасно истакнат банер).
3. Во чипот на ученикот (`studentGradeChipHtml`), доколку нема одделение, да се прикаже ознака `екст.`.

### Предлог 3: Проверка на процедурата за пренос на податоци
Да се документира во упатството за терапевтите:
- Пред да се притисне „🔄 Извези Unified Sync JSON“ на машината со база, задолжително да се притисне „Вчитај од сервер“, или извозот да се прави преку серверската скрипта `npm run export`.
