# Понеделник на PCW: од `git pull` до екран што работи

Само технички чекори. **Ниту едно име и ниту еден ученички податок не влегува
овде** — сè такво останува во локалната база на машината (правила 1 и 6).

Оваа белешка постои затоа што „git pull, рестарт, готово" **не е доволно овде**:
пулот носи **пет миграции** што твојата база сè уште ги нема, а една од нив
може да одбие — и подобро е тоа да го знаеш пред да почнеш отколку среде работа.

Работата е на **`main`**. Гранката `claude/chat-mtb-aces-folder-98qo33` носи
исто, за ако затреба.

---

## 0. Што патува, а што не

| патува низ git | останува на машината |
|---|---|
| HTML екраните, серверот, миграциите, тестовите | PostgreSQL базата со вистинските деца |

Базата **не се носи никаде и не се синхронизира преку git**. PCW веќе ја има
својата. Пулот носи само код и *празни* миграции — ниту една од петте не внесува,
не менува и не брише ученички податоци.

## 2. Повлечи

```powershell
git checkout main
git pull --ff-only
git log --oneline -1
```

Последниот ред треба да го покаже `Say how to put this on PCW…`. Ако `checkout`
се пожали на локални измени, види што се тие (`git status`) пред да ги фрлиш —
некој можеби нешто исправал директно на машината.

Ако `git pull` вели „Already up to date" а `git log` покажува постар commit,
провери на која гранка си (`git status -sb`).

## 3. Примени ги миграциите 028–032

Пет миграции (028–032) дојдоа со оваа работа. **Можно е PCW веќе да ги има** —
некои беа применети рачно таму порано, а на 12 септември беше пријавено дека
базата стои на 032. Не е важно: `setup-home-postgres.ps1` се води по
`schema_migrations` и применува САМО она што недостига, па чекорот е ист во
двата случаја — потврда ако се веќе таму, примена ако не се.

Што носат:

| | што прави | дира ли податоци |
|---|---|---|
| 028 | `CHECK`: активен интерен/интернатски мора да има одделение | не, само правило |
| 029 | го олабавува 028 — екстерен СМЕЕ да има одделение | не |
| 030 | колоната `oddelenie` на запишувањето | не, празна колона |
| 031 | опис на паралелката | не |
| 032 | каталогот предмети на МОН (707 реда понуда) | не дира ученици |

**Провери дали 028 би поминала.** Ако е веќе применета, ова е само потврда дека
базата е усогласена со неа. Таа ги валидира постоечките редови, па ако
некој АКТИВЕН интерен ученик нема одделение, миграцијата ќе одбие — точно, но
подобро е да го знаеш однапред отколку среде инсталација:

```powershell
$psql = (Get-ChildItem "C:\Program Files\PostgreSQL\*\bin\psql.exe" | Select-Object -Last 1).FullName
$url  = ((Get-Content server\.env | Select-String '^DATABASE_URL=') -replace '^DATABASE_URL=','')
& $psql $url -c "SELECT e.kind, coalesce(e.grade,'(празно)') AS odd, count(*) FROM student_enrollments e WHERE e.active AND (e.kind = 'external') <> (e.grade IS NULL OR btrim(e.grade) = '') GROUP BY 1,2;"
```

**Празен резултат = чисто, продолжи.** Ако врати редови, тоа се точно децата што
треба да добијат одделение — и тоа сега се прави во „Податоци → Одделенија"
(чекор 6). Среди ги прво, па врати се тука.

Потоа, само преку installer-от и неговиот `schema_migrations` ledger:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup-home-postgres.ps1
```

**Не пуштај поединечен SQL рачно.** Секоја миграција се применува еднаш, во своја
трансакција, заедно со својот ред во ledger-от. Рачно пуштена миграција со
`IF NOT EXISTS` не паѓа — таа ТИВКО создава втора состојба покрај првата.

## 6. Отвори и потврди со очи

Оди на **`https://pcw.tailc8965f.ts.net/Podatoci.html`** — не на копијата од
GitHub Pages. Origin значи една база; Pages копијата е друг origin со своја
меморија.

**Освежи со Ctrl+F5.** `Podatoci.html` е сменета, а прелистувачот ја држи старата.

Во јазичето **„🏫 Одделенија"** сега треба да видиш:

- имињата на децата во секое одделение, не само бројка;
- копче **„Ученици…"** што отвора список со dropdown „Додај ученик од списокот";
- секое име е копче — те носи во „Ученици" на тој ред;
- кај интерен ученик во „премести во…" **нема** „без одделение" (тоа е правилото
  од 029, кажано напред наместо како грешка).

## 7. Ако нешто тргне наопаку

| симптом | што значи |
|---|---|
| `git pull` вели „Already up to date" а кодот е стар | провери на која гранка си: `git status -sb` |
| Одделенија изгледа исто како порано | не е рестартирано, или не е Ctrl+F5 |
| „Интерен и интернатски ученик мора да има одделение" | не е дефект: тој ученик нема паралелка, стави му ја тука |
| екранот вели дека серверот не одговара | `server-control.ps1 status`, па `start` |
| `setup-home-postgres.ps1` бара лозинка за `postgres` | улогата или базата недостасува; не ја измислувај — прво провери со `verify-setup.ps1` |

## 7а. Ако агент или колега пушта тестови на PCW

**Не пуштај браузер-пакети на машината со вистинските податоци без да знаеш што
бришат.** Четири од нив (`diary-write`, `diary-schedule`, `diary-write-off`,
`records` во `server/test/*.browser.mjs`) го бришат ЦЕЛИОТ `sdnevnik` ред од
`app_state` — дневникот онака како што серверот го држи.

До 12 септември тие се штитеа со проверка на ИМЕТО на базата (`/dev|test/`) —
а вистинската база на двете машини се вика **`therapy_dev`**, па проверката
поминуваше секогаш. Сега бараат намера: без `MTB_SCRATCH_DB=1` одбиваат и
кажуваат што би избришале.

Безбедни се оние што работат во своја учебна година со измислени имиња:
`test:podatoci`, `test:podatoci-classes`, `test:evidence-ui`, `test:colleague`,
`test:uredi`, `test:nastava`, `test:fusion-ui`. И тие сепак пишуваат во базата,
па ако некој падне на пола, провери да не останале редови зад него.

`npm test` (единечните) и `npm run typecheck` се безопасни.

## 8. Враќање назад

Ниту една од петте миграции не менува податоци, па враќањето е само код:

```powershell
git checkout 361917a          # состојбата пред оваа работа
powershell -ExecutionPolicy Bypass -File scripts\server-control.ps1 restart
```

Миграциите ОСТАНУВААТ применети — не се враќаат назад, и не треба. Новите
колони (`oddelenie`, описот, каталогот предмети) едноставно не се читаат од
постариот код.

**Едно нешто сепак се враќа, и вреди да се знае:** `CHECK`-от од 029 останува во
базата, а старата верзија на `roster-write.ts` не знае за него. Значи бришењето
на одделението кај интерен ученик пак ќе враќа **HTTP 500 со
`kind_matches_grade`** наместо разбирлива реченица — токму грешката поради која
оваа гранка и постои. Правилото е точно во двата случаја; само пораката е лоша.
Тоа не губи податоци и не е причина да не се вратиш ако затреба.
