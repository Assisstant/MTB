# Пренос: HOME → WORK

Оваа белешка содржи само технички чекори. Имиња и поединечни ученички задачи
остануваат во локалната база или во приватна белешка, никогаш во Git.

## 1. Користи го активниот клон

На WORK отвори го клонот што навистина се користи и потврди ја патеката:

```powershell
$PWD.Path
git status --short --branch
git rev-parse HEAD
```

Не работи во стар резервен клон и не пуштај два сервера на портата 3000.

## 2. Повлечи и примени ги миграциите

```powershell
git pull --ff-only
powershell -ExecutionPolicy Bypass -File scripts\setup-home-postgres.ps1
powershell -ExecutionPolicy Bypass -File scripts\verify-setup.ps1
```

Миграциите се применуваат само преку installer-от и неговиот
`schema_migrations` ledger. Не пуштај поединечен SQL рачно. Миграција 027 го
поставува default-от на новите `schedule_slots.source` редови на `api`; не
увезува и не менува ученички податоци.

## 3. Потврди го Node и серверот

```powershell
node -v
powershell -ExecutionPolicy Bypass -File scripts\server-control.ps1 status
```

Ако Node од активната околина е постар од верзијата што го поддржува test
runner-от, прво стави го системскиот Node на почетокот на `PATH`. Потоа стартувај
го серверот само преку `scripts\server-control.ps1 start`.

Потврди дека scheduled tasks покажуваат кон активниот клон:

```powershell
Get-ScheduledTask -TaskName Therapy* | ForEach-Object {
  [pscustomobject]@{ Name = $_.TaskName; Dir = $_.Actions.WorkingDirectory }
} | Format-Table -AutoSize
```

## 4. Провери ја базата без печатење имиња

Во апликацијата, лентата **БАЗА** кажува која инсталација одговара, а
**ПОДАТОЦИ** кажува дали промената стигнала до PostgreSQL. Отворај преку
`start.html`, избери ја точната WORK/HOME база и не претпоставувај дека hostname
го кажува тоа; `SYNC_NAME=work/home` е авторитетот.

За дијагноза користи агрегати, не редови со имиња:

```sql
SELECT id, label, is_current FROM school_years ORDER BY id;
SELECT school_year_id, count(*) FROM schedule_slots GROUP BY 1 ORDER BY 1;
SELECT created_at::date AS den, count(*)
FROM schedule_slots GROUP BY 1 ORDER BY 1 DESC LIMIT 10;
```

Ако бројките не се очекувани, застани и спореди ги двете бази со dry-run
workflow-от во `docs/MANUAL-DB-SYNC.md`. Не restore-ирај и не force-ирај според
датум или претпоставка.

## 5. Тестови

Од `server/`:

```powershell
npm run typecheck
npm test
npm run test:evidence
npm run test:projection
npm run check:names
```

Browser/API тестовите користат измислени, изолирани fixtures и мора да ги
исчистат. Спореди ги само aggregate table counts пред и по нив.

## 6. Локални задачи

Конкретни лица, категории, неусогласени одделенија и термини се проверуваат во
локалните DB-first екрани. Ако е потребна task-листа со имиња, таа е приватен
локален документ во gitignored папка. Во оваа јавна белешка се запишува само
процесот.

## Што да не се прави

- не внесувај реални имиња, exports, `.env`, dumps или backups во Git;
- не пуштај `git push` од стар клон;
- не стартувај втор сервер кога портата 3000 веќе има listener;
- не прифаќај peer snapshot без compare, точен snapshot id и експлицитен
  `-Apply` чекор.
